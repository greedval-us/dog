# DogLive UI

Развивай интерфейс сайта DogLive в его текущем стиле. Явные новые пожелания пользователя имеют приоритет; этот скил сохраняет преемственность оформления, а не запрещает согласованные изменения дизайна. Панель MoonShine — отдельная поверхность вне области этого скила.

Все пути ниже указаны относительно корня репозитория. Сверяй правила с актуальным кодом: перечень компонентов помогает найти реализацию, но не заменяет чтение её props, slots и мест использования.

## Откуда брать образец

Перед изменением прочитай нужную часть `resources/css/app.css`, целевой компонент с его layout и одну похожую страницу. Не копируй всю страницу ради оформления нового раздела.

| Задача | Существующий образец |
| --- | --- |
| Цвета, типографика, формы, карточки, адаптивность | `resources/css/app.css` |
| Выбор layout для страниц | `resources/js/app.ts` |
| Оболочка игры: шапка, баланс, меню, подвал | `resources/js/layouts/AppLayout.vue`, `resources/js/layouts/app/AppSidebarLayout.vue` |
| Авторизация: общий фон, иллюстрация, область формы | `resources/js/layouts/AuthLayout.vue`, `resources/js/layouts/auth/AuthSimpleLayout.vue`, `resources/js/pages/auth/Login.vue` |
| Настройки: навигация и содержимое | `resources/js/layouts/settings/Layout.vue`, `resources/js/pages/settings/Profile.vue` |
| Главная и иллюстрация | `resources/js/pages/Welcome.vue` |
| Страница игры и состояние без питомца | `resources/js/pages/Dashboard.vue` |
| Русский и английский языки | `resources/js/composables/useI18n.ts`, `resources/js/locales/ru.json`, `resources/js/locales/en.json`, `resources/js/components/LanguageSwitcher.vue`, `config/localization.php` |
| Переключение светлой, тёмной и системной темы | `resources/js/composables/useAppearance.ts`, `resources/js/components/AppearanceTabs.vue` |

В `app.ts` уже настроены layouts: `Welcome` без общего layout, `auth/*` с `AuthLayout`, `settings/*` с `[AppLayout, SettingsLayout]`, остальные страницы с `AppLayout`. Сохраняй эту композицию; не добавляй вторую оболочку внутри страницы. У auth-страниц заголовок и описание передаются существующим способом через `defineOptions({ layout: ... })`.

## Визуальный язык и единый CSS

- Светлая тема: воздушный голубой фон, почти белые поверхности, синие акценты и приглушённые зелёные детали. Тёмная: глубокий сине-серый фон и светлый текст. Сохраняй мягкие градиенты, тонкие границы и ненавязчивые тени.
- Шрифт — семейство `DogLive` из существующих Gilroy Regular/SemiBold/Bold в `public/vendor/moonshine/fonts`. Иконки — `@lucide/vue`; бренд — `DogLiveBrand`. Используй имеющиеся ресурсы.
- Источник всех авторских стилей — **`resources/css/app.css`**: токены, новые классы, состояния, media queries и keyframes. Не создавай отдельные CSS-файлы для страниц, Vue-блоки `<style>` или статическое оформление через inline-style. Для динамического значения, например ширины прогресса, допустима привязка CSS-переменной; само правило остаётся в общем CSS.
- Цвета бери из существующих семантических переменных: `--background`, `--foreground`, `--card`, `--muted-foreground`, `--primary`, `--border`, `--ring`, `--surface-soft`, `--sage-surface`, `--sage-ink`, `--success`, `--success-surface`, `--danger-surface`. Новый смысловой токен добавляй в этот же файл с учётом обеих тем.
- Существующие Tailwind-классы базовых компонентов допустимы: они собираются в общий CSS. Не размножай в страницах длинные одинаковые наборы классов и отдельные палитры из произвольных значений.
- `SurfaceCard` задаёт мягкие скруглённые панели и внутренние отступы, `Heading` — иерархию заголовков, `Button` и `Input` — размеры и состояния элементов. Используй их оформление вместо локальной настройки каждого экземпляра. Не складывай поверх карточки ещё одну рамку, тень и padding без необходимости.
- Сохраняй спокойную плотность интерфейса: заголовок, понятное действие, содержимое. Крупная декоративная иллюстрация уместна на главной и в авторизации; рабочие игровые экраны должны оставлять место для данных и действий.

## Переиспользование компонентов

Общие компоненты находятся в `resources/js/components`, базовые элементы Starter Kit — в `resources/js/components/ui`.

| Компонент | Как применять |
| --- | --- |
| `DogLiveBrand`, `DogLiveFooter`, `DogLiveNavigation` | Используй общие бренд, подвал и навигацию. Desktop и mobile используют один список разделов. |
| `SurfaceCard` | `title`, `description`, обычный slot содержимого и при необходимости slot `header`. |
| `Heading` | Заголовок с необязательным описанием; `variant="small"` для раздела. Учитывай уже существующий h1 в layout. |
| `FormField` | `id`, `label`, `error`, `hint`; привязывай выданный slot-параметр `field` к вводу через `v-bind="field"`, чтобы сохранить связь label, ошибки и подсказки. |
| `FormActions` | Общая отправка формы: `processing`, `saved`, `label`, при необходимости `testId`. |
| `PasswordInput`, `TextLink`, `InputError` | Существующие поведение, подписи, ссылки и сообщения формы. |
| `EmptyState` | `title`, `description` и slot для доступных действий. Сейчас содержит текст о дружбе и лапу; для иных сценариев при реальной необходимости расширь общий API, не копируй разметку. |
| `Button`, `Input`, `Card`, `Dialog`, `Checkbox`, `DropdownMenu` | Сохраняй поведение и семантику Starter Kit/Reka UI. Ссылку с оформлением кнопки собирай через `Button as-child` и Inertia `Link`. |

Повторяющуюся структуру с общей ответственностью выноси в компонент. Не создавай абстракции для гипотетических страниц. При появлении нового варианта сначала проверь, можно ли выразить его props, slots или существующими вариантами; расширяй API по фактической потребности. Для новых CSS-классов придерживайся используемых имён по назначению: `form-*`, `field-*`, `surface-*`, `doglive-*` или имени раздела.

## Формы, данные и состояние страницы

- Используй имеющиеся Inertia-формы и маршруты Wayfinder из `@/routes` и `@/actions`; сохраняй серверную валидацию, `processing`, сообщения ошибок и успеха. Для соответствующих изменений применяй проектные скилы Inertia, Wayfinder и Fortify.
- Интерфейс поддерживает русский и английский языки. Получай видимые строки, подсказки, alt и доступные подписи через `useI18n().t`; добавляй и обновляй одинаковые ключи в `resources/js/locales/ru.json` и `resources/js/locales/en.json`. Параметры вида `{username}` должны совпадать в обоих переводах. В русских текстах сохраняй обращение на «ты». Не выводи технические подробности реализации в пользовательских действиях.
- Используй существующий `LanguageSwitcher` и серверный выбор языка: настройка аккаунта → cookie → `config/localization.php`. Не создавай параллельное хранение языка. Числа форматируй с текущей locale. Серверные сообщения и письма переводятся отдельно в `lang`; не подменяй их клиентскими словарями.
- Отображай реальные данные пользователя и питомцев. Отсутствие собаки — нормальное пустое состояние: не подставляй демонстрационного питомца, характеристики или баланс. При появлении механизма получения питомца подключай настоящее действие.
- `public/images/doglive-rey.png` сейчас служит оформлением главной и авторизации. Наличие этой иллюстрации не означает владение собакой.
- Добавляй в меню существующие доступные сценарии. Не заполняй его неработающими пунктами будущей игры. Концепция механики сама по себе не означает, что её поля и обработчики уже реализованы.
- У новой функции учитывай нужные ей состояния: загрузка, отсутствие данных, содержимое, ошибка, выполнение и результат действия. При замене реализации удаляй ставшие ненужными компоненты и стили после проверки их использования.

## Адаптивность и движение

- Продолжай текущие responsive-правила в общем CSS. Существующие точки адаптации: 1100, 900, 650 и 380 px. Это ориентиры текущего layout, а не запрет на обоснованное дополнение.
- На планшете sidebar становится компактным; на телефоне используется общее раскрывающееся меню. Настройки и формы перестраиваются, декоративная часть авторизации скрывается. Сохраняй доступность действий и не дублируй навигацию новой страницей.
- Длинный ник, баланс, ошибка и заголовок не должны расширять документ. Используй переносы, `min-width: 0` и локальную прокрутку таблиц там, где она нужна. Не маскируй проблему глобальным `overflow-x: hidden`.
- Анимация служит обратной связи. Ориентируйся на имеющиеся короткие переходы около 0.18 s; новое движение задавай в общем CSS, преимущественно через opacity и transform. Учитывай существующий `prefers-reduced-motion`. Не добавляй параллакс, автопрокрутку или постоянное декоративное движение без задачи на такой эффект.
- Сохраняй видимый фокус, подписи полей, доступные имена иконок, управление клавиатурой, фокус и закрытие диалогов. Ошибку или выбранное состояние показывай не только цветом. Критичные действия должны быть доступны без hover.

## Проверка изменения

Для изменения UI проверь узкий и широкий экраны, обе темы и RU/EN; при затрагивании layout добавь планшет. Рабочие ориентиры: 320/390, 768 и 1440 CSS-пикселей. Проверяй изменённые состояния и реальные действия, а при изменении общего компонента — его репрезентативных потребителей в игре, настройках или авторизации.

Запускай проверки по объёму изменения и текущим scripts в `package.json`: TypeScript — `npm run types:check`, сборка — `npm run build`, форматирование/линтер — настроенный Vite Plus для затронутых файлов. Новые тесты нужны для изменённого поведения с полезным регрессионным покрытием; для чистого оформления не создавай тесты, повторяющие CSS. Не заявляй о визуальной проверке без наблюдения в браузере.

В итоговом diff проверь отсутствие повторной оболочки, дублированных компонентов/стилей, демонстрационных данных и изменений вне задачи. В самом скиле и проектной документации сохраняй переносимые пути без привязки к компьютеру участника команды.
